# Проверка локальной транскрибации

Все команды выполняются из корня репозитория. Используем Python 3.13, отдельное
окружение, faster-whisper и многоязычную small (около 486 МБ). Модель работает
на CPU в INT8. Для самой транскрибации PyTorch и Community-1 не нужны.
Диаризация запускается отдельно, как описано ниже. Существующее окружение
Whisper не переустанавливаем, интерпретатор VS Code не меняем.

## Установка и отдельное скачивание модели

```bash
python3.13 -m venv audio_module/.venv
audio_module/.venv/bin/python -m pip install --only-binary=:all: -r audio_module/requirements.txt
audio_module/.venv/bin/python -m audio_module.cli download
```

Интернет нужен только для установки пакетов и скачивания публичных весов.
Команда download проверяет суммарный размер нужных файлов и отказывается
скачивать больше 1 ГБ. API-ключи не требуются. Команда transcribe сама ничего
не скачивает: если локальной модели нет, возвращается ошибка.

## Проверка первых 60 секунд

```bash
audio_module/.venv/bin/python -m audio_module.cli transcribe \
  '/Users/malika/Desktop/Hackhton доки просто/Совещание №1.mp3' \
  --max-seconds 60 \
  --output audio_module/results/meeting-1-first-60s.json
```

Для первых 120 секунд замените 60 на 120 и используйте другое имя результата.
Для полной записи до 10 минут уберите --max-seconds. Более длинная полная запись
отклоняется; режим отрывка декодирует только начало, а не весь файл в память.
Язык по умолчанию определяется автоматически. Для отдельной русской или
казахской записи можно указать --language ru или --language kk. Автоопределение
не гарантирует правильное распознавание переключений языков внутри фразы.

В JSON есть полный text и segments: start/end в секундах от начала исходной
записи, text и speaker: null. processing содержит режим prefix/full, запрошенный
лимит, фактически обработанный интервал, оценку общей длительности,
is_partial и время обработки. Оценка общей длительности берётся из контейнера
и может быть неточной. Диаризация имеет status: not_run и понятную причину.
Статус no_speech_detected означает, что модель не выдала реплик; это не
доказательство отсутствия речи в исходной записи.

## Проверки результата

1. Откройте JSON локально. Сверьте несколько фраз с записью и проверьте имена,
   числа и казахские слова. Не отправляйте запись или JSON во внешние сервисы.
2. Проверьте, что временные метки упорядочены и находятся внутри обработанного
   интервала. Для отрывка длинной записи должны быть mode: prefix и is_partial: true.
3. У всех сегментов должен быть speaker: null. Метки говорящих не выдумываются.
4. Отключите интернет и повторите команду в новом процессе. Для проверки
   отсутствующей модели передайте --model-dir audio_module/models/missing:
   должна появиться ошибка, а не автоматическая загрузка.
5. Несуществующий, пустой и повреждённый MP3 должны завершаться ошибкой.
   Успешный результат не создаётся при сбое. Старый JSON при неудачной повторной
   обработке остаётся на месте — ориентируйтесь на код завершения команды.

## Подключение из Python

```python
from audio_module import transcribe_mp3, save_json

result = transcribe_mp3('/Users/malika/Desktop/Hackhton доки просто/Совещание №1.mp3', max_seconds=60)
save_json(result, 'audio_module/results/meeting-1-first-60s.json')
```

Модуль не меняет общий backend API. Функция блокирующая: backend должен запускать
её в своём фоновом обработчике. Модель загружается при каждом вызове; для первой
версии обрабатываем одну запись за раз. Результаты сохраняются атомарно в UTF-8.

## Приватность и Git

Вызов transcribe использует локальные файлы, HF_HUB_OFFLINE=1 и
local_files_only=True. Телеметрия Hugging Face отключена. Перед импортом ONNX
Runtime задаётся ORT_DISABLE_TELEMETRY=1, дополнительно вызывается
disable_telemetry_events(). Текст не выводится
в терминал. Исходная запись остаётся по исходному пути и не копируется в Git.

В audio_module/.gitignore разрешены только явно перечисленные исходники,
файлы зависимостей, тесты и эта инструкция. Окружения, модели, записи,
JSON и любые дополнительные файлы внутри audio_module игнорируются.
Сохраняйте результаты в audio_module/results; для другого пути вызывающая
сторона отвечает за исключение из Git. Не используйте git add -f.

```bash
git status --short --untracked-files=all
git check-ignore audio_module/.venv audio_module/models audio_module/results
```

## Доступ к Community-1 и скачивание

1. Откройте https://huggingface.co/pyannote/speaker-diarization-community-1,
   войдите в аккаунт и примите условия доступа к модели.
2. На https://huggingface.co/settings/tokens создайте токен с правом чтения
   доступного вам репозитория модели. Не присылайте токен в чат.
3. В своём терминале из корня проекта выполните:

```bash
audio_module/.venv/bin/python -m audio_module.download_diarization
```

Команда использует существующий локальный вход Hugging Face, если он есть,
либо запросит токен через скрытый getpass-ввод. Она не записывает введённый
токен на диск, в исходники, аргументы команд или Git. Она проверяет доступ и
размер пяти нужных файлов до скачивания и останавливается, если они больше
100 МБ. Остаток согласованного общего бюджета также нужно учитывать перед
повторными скачиваниями. Каталог модели: audio_module/models/community-1.

После скачивания для обработки токен не нужен. Перед импортом библиотек
worker отключает метрики pyannote, OpenTelemetry, Hugging Face и ONNX Runtime,
включает офлайн-режим HF и блокирует сетевые подключения Python. Загружается
только локальный каталог Community-1. Реальная повторная проверка с
HF_HUB_OFFLINE=1 и блокировкой сетевых вызовов Python выполнена успешно;
подробности ниже. Физическое отключение Wi-Fi в этой проверке не проверялось.

## Запуск диаризации тех же 60 секунд

```bash
audio_module/.venv/bin/python -m audio_module.cli diarize \
  '/Users/malika/Desktop/Hackhton доки просто/Совещание №1.mp3' \
  --transcript audio_module/results/meeting-1-first-60s.json \
  --output audio_module/results/meeting-1-first-60s-diarized.json
```

Интервал берётся из processing исходного JSON: начало 0, конец 60.
Команда не запускает Whisper повторно. Существующий PyAV декодирует этот
отрывок в моно 16 кГц, временный массив передаётся отдельному процессу
.venv-diarization/bin/python и удаляется после завершения. Модель получает
только аудио; текст для её работы не требуется. Системный FFmpeg не нужен для
этого пути: pyannote получает готовый waveform, а не открывает MP3 через
TorchCodec. Предупреждение о недоступном декодере TorchCodec допустимо только
при успешной проверке импорта и этого пути обработки.

Код завершения CLI: 0 — модель выполнилась (ok или no_speech_detected);
2 — результат сохранён, но диаризация unavailable/failed; 1 — ошибка чтения
входного JSON или сохранения результата. Путь output должен отличаться от
transcript, чтобы исходная транскрибация оставалась отдельным файлом.

## Для Улданы: вызов из backend

Публичные transcribe_mp3 и save_json сохранены. Backend работает в окружении
Whisper и вызывает новую блокирующую функцию из своей фоновой задачи:

```python
from audio_module import transcribe_mp3, save_json
from audio_module.diarize import add_diarization

mp3_path = '/Users/malika/Desktop/Hackhton доки просто/Совещание №1.mp3'
transcript = transcribe_mp3(mp3_path, max_seconds=60)
result = add_diarization(mp3_path, transcript, timeout_seconds=600)
save_json(result, 'audio_module/results/meeting-1-first-60s-diarized.json')
```

Если транскрипт уже есть в памяти или JSON, передайте его напрямую, не вызывая
transcribe_mp3 заново. add_diarization возвращает новый dict и не изменяет
входной объект. Сохраняются schema_version, общий status транскрибации, text,
processing и start/end/text каждого сегмента. Меняется только speaker и
раздел diarization. Проверять нужно именно result['diarization']['status']:

| Статус | Значение |
|---|---|
| not_run | Диаризация ещё не вызывалась |
| unavailable | Нет модели/окружения/аудио/нужной библиотеки; есть code и reason |
| failed | Сбой процесса, таймаут или некорректные данные; транскрипт сохранён |
| ok | Модель действительно выполнилась и вернула интервалы говорящих |
| no_speech_detected | Модель выполнилась, но интервалов не вернула |

На компьютере backend нужны оба окружения, локальная small и локальная
Community-1. Пути можно переопределить параметрами model_dir и
python_executable в add_diarization. Одновременно обрабатываем одну запись.
Для корректного сопоставления MP3 должен быть тем же файлом, из которого
получен транскрипт; для старого JSON без хеша это ответственность вызывающего
модуля. Интервал проверяется, но совпадение содержания двух файлов не доказывается.

## Правила сопоставления

Используются SPEAKER_00, SPEAKER_01 и далее в порядке первого появления в
данной обработке. Это не реальные имена и не постоянные идентификаторы между
записями. Сохраняются обычные turns с пересечениями и exclusive_turns.
Сопоставление использует обычные интервалы, чтобы не скрыть перебивания.

При единственном говорящем требуется покрытие хотя бы 50% сегмента.
Любое обнаруженное пересечение разных голосов, смена спикера внутри сегмента,
отсутствие речи или недостаточное покрытие оставляют speaker: null.
Причина находится в diarization.assignments по segment_index:
assigned, overlapping_speech, speaker_change_within_segment,
no_matching_speech, insufficient_coverage. Покрытие — доля времени, не
вероятность правильности модели. Без временных меток слов текст между
несколькими спикерами автоматически не разрезается.
