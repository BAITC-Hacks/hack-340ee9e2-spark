# Frontend QA — интеграция

Фактически проверено 23 сентября 2026 года в локальном Google Chrome через
`tests/smoke_frontend.py`, с настоящей записью и обработкой первых 60 секунд.

- [x] Страница, JS и CSS отдаются одним FastAPI-сервером.
- [x] Health-запрос успешен.
- [x] Выбор настоящей MP3 и показ имени файла.
- [x] Выбор первых 60 секунд по умолчанию.
- [x] «Обрабатываем аудио…» и запрет повторной отправки/смены файла.
- [x] Ровно один POST /analyze-audio, без polling /api/meetings.
- [x] Саммари и все 15 реальных реплик показаны.
- [x] Отметки начала/конца, 12 меток SPEAKER и 3 неопределённых говорящих.
- [x] Причины неопределённости и предупреждение о частичной записи видны.
- [x] Пустой список поручений показан честно: анализатор вернул 0 задач.
- [x] DOCX получен через POST /export-docx; содержимое проверено программно.
- [x] Нет ошибок JavaScript, внешних запросов страницы и горизонтального
      переполнения документа на ширинах 1440 и 390 px.

Не подтверждено этим настоящим отрывком: качество извлечения задач (их найдено
0), казахская/смешанная запись, ручное редактирование, визуальная верстка DOCX
в Word. Непустые поручения и отсутствие ответственного/срока проверены тестами
backend на подготовленных текстовых примерах. Drag-and-drop, выбор .mpeg,
ошибка отключённого сервера и пустая отправка требуют отдельного ручного прохода.

Дата совещания и число участников не поддерживались API и больше не показаны
как работающие поля. Относительные сроки анализатор сохраняет текстом.
